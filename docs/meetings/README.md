## 세부 사항

### ~10/16 이전 주제 회의, 교수님 면담
- 이전 주제는 학생 관점 수강신청 도우미(SSU:gang)였음
- 10/16 교수님 면담 의견
  - 학생 관점은 뻔함. 행정팀·교수진·학교 관점으로 돌리면 새로움
  - 동기에는 수치 근거가 필수
  - 핵심 기능은 1~2개면 충분
  - NLP는 중심이 아니어도 됨
- 교수님이 제안한 주제 중 하나가 강의실·시간·분반 배정이었음

### 10/18 아이디어 확정
- 교수 희망 수집과 의견 조율을 돕는 SSU:room으로 정함

### 10/23 인터뷰
- 학사팀 1명(짧게), AI소프트웨어학부 학과사무실 조교 1명(약 40~50분)
- 학사팀은 각 학과가 SAP에 입력한 것을 2차 점검만 함. 실제 편성은 학과사무실 조교가 함
- 확인한 사실
  - 자동 배정 도구는 없음. 엑셀로 맞춘 뒤 SAP에 입력함
  - 규모는 두 학과 합쳐 강의 약 100개이고, 조교 1명이 맡음
  - 겹친 건당 연락 왕복은 1~10번, 답은 최대 1주 걸림
- 우선순위는 원칙상 연차순이지만, 실제로는 교수들이 자발적으로 양보함 (선임 양보, 저녁 시간 자청, 9시 요청)
- 조교님: "이런 플랫폼은 있으면 바로 써 보고 싶다"
- 정리본은 응답자 정보 보호를 위해 저장소 밖에 둠

### 10/24 기획 회의
- 실제 사용자를 학과사무실 조교로 정함. 동기와 문제 상황도 조교 중심으로 씀
- 인터뷰 보충
  - 교양필수는 보통 10:30~15:00
  - 교양선택은 범위에서 뺌
  - 전공기초는 분반을 문화관·정보관에 나눠 배정함
- 시안 v2: 교수·조교 화면만 둠. 학사팀 연계와 강의실 조회는 뺌

### 11/3 발표 자료 검수
- 덱 19쪽 기준으로 슬라이드마다 말할 것을 정함
- 덱 수정
  - 우리가 해결하지 않는 문제(교양선택, 다른 단과대 조율)는 뺌
  - 자동 초안 설명 순서를 규칙 → 선호 → 우선순위로 바꿈
  - 양보 의사 상자, 회신 해석 정확도 90% 줄, 배정 비교 실험 상자는 뺌
- 발표는 한 명이 진행하고 다른 팀원이 슬라이드를 넘김. 7분 엄수
- 예상 질문 답변 준비: 왜 학교는 자동 배정을 안 쓰나, 인터뷰는 몇 명인가
