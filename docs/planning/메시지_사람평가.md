# 조율 메시지 사람 평가: 채점 기준

조율 메시지(교수에게 보내는 글)는 정답이 하나가 아니라 사람이 읽고 점수를 매긴다.
코드 검사(`check_message`)가 이미 막는 것(희망·대안 문자열 누락, 연차·우선순위 단어, 숨긴 상대 교수 이름)은 그대로 두고, **코드로는 못 잡는 것**을 사람이 본다.

## 1. 무엇을 채점하나

- 상황 25개(s1~s25)마다 **언어 모델 메시지 1개 + 틀 문장 메시지 1개(기준선)** = 50개
- 순서를 섞고 `g01`~`g50` 번호만 붙였다. 채점표에는 어느 방식인지 적지 않는다
- 언어 모델 글이 코드 검사에 걸리거나 모델 호출이 실패하면 틀 문장이 대신 나간다. 그런 것도 서비스에서 실제로 나가는 글이라 그대로 채점한다

## 2. 채점 칸

| 칸 | 값 | 0을 주는 경우 |
|---|---|---|
| 내용_맞음 | 1 / 0 | 받는 교수, 과목·분반, 차수, 처음 희망, 대안(요일·시각·강의실)이 옆 칸과 하나라도 다르게 읽힌다. 예: 대안 시각은 맞게 적었지만 "A안을 추천드립니다"처럼 학과가 정하지 않은 뜻을 붙임 |
| 지어낸말_없음 | 1 / 0 | 입력에 없는 사실을 만들었다. 예: 겹친 이유("강의실 공사로"), 상대 교수의 사정, 마감 날짜, "다른 교수님들은 모두 동의하셨습니다" |
| 금지내용_없음 | 1 / 0 | 연차·우선순위 이유("선임이셔서", "'꼭' 표시가 있어서"), 상대 교수의 기타 요청, **겹친상대 칸에 "이름 숨김"이라고 적힌 상황에서** 상대 교수·강의 이름 |
| 자연스러움_1to5 | 1~5 | 5 = 그대로 보내도 됨, 4 = 사소한 어색함, 3 = 고치고 보내고 싶음, 2 = 읽기 불편, 1 = 보내면 안 됨 |
| 메모 | 자유 | 0을 줬으면 이유 한 줄. 애매했던 것도 적는다 |

- 1/0 칸은 **문장 하나라도** 걸리면 0이다
- 2차·3차 메시지는 상대 교수를 쓰지 않아도 된다. 지난 조건을 반영했다는 말이 있으면 `지난조건` 칸과 맞는지 본다
- 회신 기한·재알림 안내(마지막 문단)는 모든 메시지에 같게 들어가는 문장이라 지어낸 말로 보지 않는다

## 3. 누가, 어떻게

- 채점표: `eval/labels/message_scores.csv` (엑셀로 열고 빈 칸을 채운 뒤 CSV로 저장)
- 채점 전에는 `eval/results/message_llm_<시각>.csv`(번호 ↔ 방식, 자동 검사 결과)를 열지 않는다
- 집계: `python eval/run_coord.py message-score eval/results/message_llm_<시각>.csv`
  - 방식별 개수, 세 칸의 1 비율, 자연스러움 평균, 0이 하나라도 있는 번호

## 4. 한계

- 틀 문장은 모양이 늘 같아 채점하는 사람이 알아볼 수 있다. 번호를 섞었지만 완전한 블라인드는 아니다
- 채점자가 한두 명이라 일치도를 내기 어렵다. 두 명이 채점하면 같은 표를 따로 채운 뒤 비교한다
- 상황은 실제 시간표로 꾸민 가상 상황이고, 교수 이름은 가명이다

- 언어 모델 글 25개 모두 코드 검사를 통과해 그대로 나갔다 (틀 문장으로 넘어간 것 0개)

|---|---|---|

언어 모델 글에서 나온 문제

| 문제 | 개수 | 번호 | 예 |
|---|---|---|---|
| 둘째 줄이 "…조율"로 끝나 문장이 아님 (자연스러움 −2) | 9 | g03 g04 g07 g11 g12 g18 g23 g37 g42 | "2026-1학기 빅데이터분석 01 분반 1차 조율" |

| 대안을 잘못 설명함 | 1 | g17 | C안은 월·수 13:30인데 "처음 희망하신 월·수 12:00도 대안 C로 포함" |

- 코드 검사(`check_message`)는 50개 모두 통과로 보았다. 검사는 이름·희망·대안 줄이 맞는지만 보고, 설명 문장 속 이유나 대안 설명이 사실인지는 보지 않는다. 사람 평가가 필요한 이유가 여기서 확인됐다
- 이번 결과로는 틀 문장이 모든 칸에서 언어 모델과 같거나 나았다. 내용·지어낸 말에서 0을 받은 곳은 모두 언어 모델이 입력에 없는 설명을 덧붙인 곳이다

이 결과로 바꾼 것 (11/23)
- 인사·제목 줄·대안 목록·마지막 문장은 틀 문장이 만들고, 언어 모델은 **상황 설명 문단 하나만** 쓴다. 둘째 줄 문제와 대안 줄이 바뀌는 문제가 구조상 없어진다
- 설명 문단에 코드 검사를 더했다: 대안 A·B·C를 따로 설명함, 처음 희망·지난 조건에 없는 시각, 이유를 덧붙이는 말("때문", "배정되어", "중복" 등, 2·3차는 "겹" 포함), 빈 문단. 걸리면 틀 문장이 나간다
- 바꾼 뒤 결과는 새 채점표로 다시 잰다 (6절). 위 1차 숫자는 바꾸기 전 기록으로 그대로 둔다

## 6. 다시 재기 (2차, 11/23)

- 같은 상황 25개로 언어 모델 25개 + 틀 문장 25개를 다시 만들고 순서를 새로 섞었다 (시드 13). 이제 인사·제목 줄이 두 방식에서 같아 1차보다 구별이 어렵다
- 메시지: `eval/results/message_llm_20261123-1547.csv`, 채점표: `eval/labels/message_scores_v2.csv` (기준은 2절 그대로)
- 언어 모델 글 25개 모두 새 검사를 통과했다 (틀 문장으로 넘어간 것 0개)
- 채점: 최재성 1명

| | 틀 문장 (기준선) | 언어 모델 1차 (바꾸기 전) | 언어 모델 2차 (설명 문단만) |
|---|---|---|---|
| 내용_맞음 | 1.00 | 0.96 | 0.96 |
| 지어낸말_없음 | 1.00 | 0.88 | **1.00** |
| 금지내용_없음 | 1.00 | 1.00 | 1.00 |
| 자연스러움 평균 (1~5) | 5.00 | 3.92 | **4.72** |

- 지어낸 이유 3개 → 0개, 제목 줄 문제 9개 → 0개(구조상 없음). 자연스러움 5점이 아닌 것은 6개(4점 5개, 3점 1개)
- 남은 문제
  - g08 (내용 0, 자연스러움 3): 프롬프트 예시의 자리표시 "(상대 교수) 교수님"을 그대로 베껴 실제 상대 교수 이름이 빠졌다. 검사에 상대 이름이 들어갔는지 보는 항목이 없어 통과했다
  - 4점 5개: "처음 희망하신 화 12:00~14:45 연강 시간이"처럼 희망 시간을 문장에 끼울 때 조사가 어색함 (g04 g12 g23 g24 g38)
- 그래도 틀 문장이 모든 칸에서 같거나 나았다. 언어 모델은 같은 뜻을 상황에 맞춰 풀어 쓰지만, 이번 25개 상황은 틀 문장으로도 충분한 모양이었다

채점 뒤 고친 것 (위 2차 숫자에는 반영되지 않음)
- `check_body`에 두 가지를 더했다: 1차이고 상대 공개 설정이면 상대 교수·강의 이름이 문단에 있어야 함, "(상대 …)" 같은 자리표시가 남으면 막음. 프롬프트 예시도 자리표시 대신 가짜 이름으로 바꿨다
- 2차 언어 모델 글 25개에 새 검사를 돌리면 g08 하나만 걸리고 나머지 24개는 그대로 통과한다 (걸리면 틀 문장이 나간다)
- (11/23 진짜 솔버 흐름 확인 뒤) 2·3차 상황 설명에서 지난 조건을 따옴표 대신 괄호 "조건(…)을"로 넘긴다. 따옴표로 넘기면 `…종료"을`처럼 조사가 어긋났다. 조건 표시는 같은 시각이면 요일을 묶는다 ("매일 15:00 전 종료")
