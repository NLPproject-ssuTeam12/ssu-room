# 답장 쓰기·정답 달기 안내

처음 보는 사람도 이 문서만 보고 따라 할 수 있게 썼다. git을 몰라도 된다. 팀 구글 시트만 있으면 된다.

## 0. 이게 뭐 하는 건가요

우리 시스템은 교수님 답장을 읽고 이렇게 정리한다.

> 답장: "A나 B 괜찮아요. 수요일은 5시 전에 끝나야 해요."
> → 판정 **조건부**, 고른 안 **A, B**, 조건 **수요일 17:00 전 종료**

이걸 얼마나 잘하는지 숫자로 재려면 **시험 문제(답장)와 정답**이 있어야 한다.

- **1부:** 모두가 교수님인 척 답장을 20개씩 쓴다 → 시험 문제
- **2부:** 재성이 각 답장에 정답을 단다 → 정답 (이걸 "라벨"이라고 부른다)
- 그다음 재성이 키워드 방식과 언어 모델 방식을 돌려 정답과 비교한다

## 꼭 지킬 것

1. **직접 쓴다.** ChatGPT·Gemini 같은 AI로 답장을 만들거나 다듬지 않는다. 팀 원칙이다. AI가 쓴 문장으로 AI를 평가하면 점수가 실제보다 높게 나온다
2. **실제 교수님 이름이나 실제 사정을 쓰지 않는다.** 시간표는 실제 값이지만 상황은 가상이다
3. **이 문서의 예시 문장을 그대로 쓰지 않는다.** 비슷한 뜻이라도 자기 말로 쓴다
4. 답장을 쓸 때 "이건 조건부로 쓴 거야" 같은 의도를 적지 않는다. 정답은 2부에서 따로 단다

## 누가 언제

| 할 일 | 누가 | 마감 |
|---|---|---|
| 1부 답장 20개 | 4명 모두 | 재성이 단톡에 공지 |
| 2부 정답 달기 | 재성 | 1부 끝나고 |

각자 기호: 민우 `m`, 대원 `d`, 하윤 `h`, 재성 `j`

## 1부. 답장 쓰기 (모두, 1인당 20개)

### 1단계. 팀 구글 시트 열기

1. 단톡에 올라온 **구글 시트 링크**를 연다
2. 아래 탭에서 **자기 이름 탭**(민우(m) / 대원(d) / 하윤(h) / 재성(j))을 누른다
3. s1부터 s20까지 한 줄씩 미리 채워져 있다. 한 줄 = 상황 하나
   - 과목·처음 희망·대안 A·B·C·특징은 미리 채워 둔 칸이라 고치지 않는다
   - 교수님이 받은 메시지 원문을 보고 싶으면 **메시지 전문** 탭을 본다 (저장소에서는 `eval/상황_메시지.md`)

상황은 **2026-1·2학기 AI소프트웨어학부 실제 개설 강좌 시간표**로 만들었다. 과목명·분반·강의실·시간은 실제 값이고, 교수 이름(가·나·다 …)은 가명이다.
처음 희망·겹친 상대·대안은 실제 시간표로 꾸민 가상 상황이다. 대안 중 하나는 그 분반이 실제로 배정된 시간이다.

메시지는 이렇게 생겼다 (s20):
```
커 교수님, 안녕하세요. 학과사무실입니다.
2026-2학기 컴파일러 01 분반 시간표 1차 조율 안내드립니다.

희망하신 시간(화·목 15:00)이 터 교수님의 알고리즘 02 분반과 겹칩니다.

A  화·수 16:30~17:45 · 정보과학관 21303
B  화·목 16:30~17:45 · 정보과학관 21303
C  화·목 13:30~14:45 · 정보과학관 21303

가능한 안을 골라 주시거나, 모두 어려우시면 가능한 시간을 적어 주세요. 회신 기한은 1주이며, 기한 전에 한 번 더 알려 드립니다.
```
- 2차·3차 메시지(s4, s7, s9, s14, s17, s19)는 지난번 답장에서 준 조건을 반영한 대안이다
- "연강"은 일주일에 한 번, 같은 날 두 칸(2시간 45분)을 이어서 하는 수업이다
- 대안이 둘뿐인 메시지도 있다. 요일마다 시간이나 강의실이 다른 대안도 있다

### 2단계. 답장 쓰기

**상황 하나에 답장 하나씩, 20개**를 쓴다. 그 메시지를 받은 교수님이 되어 답한다.

| 칸 | 쓰는 것 |
|---|---|
| 답장 (노란 칸) | 답장 글 |
| choice | 거의 비워 둔다. 교수님이 글 대신 화면 버튼을 눌렀다고 치고 싶을 때만 `A`·`B`·`C`, 또는 `none`(모두 어려움)을 고른다 |

오른쪽 위 **작성** 칸에 쓴 개수가 나온다 (예: `12 / 20`).

### 3단계. 골고루 쓰기

20개를 쓸 때 아래 네 종류가 **대략 5개씩** 섞이게 쓴다. 어느 상황에 어느 종류를 쓸지는 자유다.

| 종류 | 이런 답장 |
|---|---|
| 받아들임 | 안 하나(또는 여러 개)를 고르고 끝 |
| 조건 붙여 받아들임 | 안을 고르면서 "다만 ~" 하고 조건을 붙임 |
| 거절 | 다 어렵다고 함. 대신 되는 요일·시간을 말하기도 함 |
| 애매함 | 어느 안인지 모르겠음, 나중에 연락하겠다고 함, 질문만 함 |

말투도 실제 교수님처럼 여러 가지로 쓴다. 아래에서 여러 개를 섞어 본다.

- 안 가리키기: "A로", "두 번째 거", "아침 수업으로", "미래관에서 하는 걸로"
- 시각: "5시", "17시", "오후 다섯 시", "4시 반"
- 요일: "수요일", "수", "월수", "금요일 빼고"
- 조건 두 개 이상, 순서 말하기("A가 제일 좋고 안 되면 C")
- 뒤집기("좀 이르긴 한데 B로 할게요")
- 아주 짧게("넵 A"), 길게(인사, 사정 설명까지)
- 오타, 띄어쓰기 틀림
- 시간표와 상관없는 말 섞기(학회 일정, 조교 배정 부탁 등)

### 4단계. 다 쓰면

시트는 자동 저장된다. 20개를 다 채우면 단톡에 "다 씀"이라고만 남긴다. 재성이 시트에서 바로 모은다.

## 2부. 정답 달기 (재성)

정답은 팀 구글 시트의 **정답(재성)** 탭에 단다. 같은 상황의 답장 4개가 붙어 있어서 대안을 한 번 보고 이어서 달면 된다. **시스템 결과를 보지 않고** 단다.

### 1단계. 정답 탭 열기

노란 칸(kind ~ memo)을 채운다. kind와 slots는 드롭다운이고, slots는 `10:30, 15:00`처럼 교시를 직접 써도 된다.

### 2단계. 판정(kind) 고르기

위에서부터 차례로 물어보고, 처음 "예"가 나오는 곳에서 멈춘다.

| 순서 | 질문 | 예 → kind |
|---|---|---|
| ① | 화면 버튼(choice)에 A·B·C가 있나? | 그 안을 고른 것. 글에 조건이 있으면 `조건부`, 없으면 `수용` |
| ② | choice가 `none`이거나, "다 어렵다"고 했나? | `거절` |
| ③ | 받아들인 안이 **분명히** 있나? | 조건이 붙었으면 `조건부`, 없으면 `수용` |
| ④ | 안은 안 고르고 "○요일이면 돼요"처럼 되는 시간만 말했나? | `거절` |
| ⑤ | 위에 다 해당 없음 (어느 안인지 모름, 나중에 연락, 하나만 어렵다고 함) | `확인 필요` |

### 3단계. 나머지 칸 채우기

없는 칸은 비운다.

| 칸 | 뜻 | 쓰는 법 |
|---|---|---|
| picks | 받아들인 안. 좋아하는 순서대로 | `B` / `A,B` / `C,A` |
| days | 된다고 한 요일 | `화목` / `월화수금` |
| slots | 된다고 한 교시(시작 시각) | `오전` / `점심` / `오후` / `늦은 오후` / `저녁` 또는 `10:30, 15:00` 또는 `15:00 이후` |
| day_slots (선택) | 요일마다 되는 교시가 다를 때만 (11/22) | `화=오전; 목=13:30,15:00`. 교시를 비우면 그 요일은 아무 교시나 (`화=; 목=오후`). 이 칸을 쓰면 days·slots는 비운다 |
| end_before | "○요일은 ○시 전에 끝나야" | `수 17:00`. 여러 개면 `수 17:00; 금 16:00` |
| memo | 헷갈린 이유, 정답 칸에 못 넣은 것 (질문·추가 요구·사유) | 짧게: `질문`, `사유`, `애매: C 수용?` |

교시는 09:00, 10:30, 12:00, 13:30, 15:00, 16:30, 18:00, 19:30 여덟 개다. 이름과 교시: 오전 = 09:00·10:30, 점심 = 12:00, 오후 = 13:30·15:00·16:30, 늦은 오후 = 16:30, 저녁 = 18:00·19:30 (6시 시작은 저녁, 11/22). 연강은 두 교시를 쓴다 (13:30 연강 = 13:30·15:00). 이름과 시각을 같이 적으면 둘이 합쳐지니, 답장에 나온 말 하나만 적는다 ("3시나 4시 반" → `15:00, 16:30`)

days와 slots를 같이 적으면 "그 요일들 모두에 그 교시"로, slots만 적으면 "다섯 요일 모두에 그 교시"로, days만 적으면 "그 요일들은 아무 교시나"로 읽는다. "화요일은 오전, 목요일은 오후"처럼 요일마다 다르면 day_slots 칸에 적는다 (11/22 요일별 교시)

### 예시

| 상황 | 답장 | kind | picks | days | slots | end_before |
|---|---|---|---|---|---|---|
| s1 | B로 부탁드립니다. | 수용 | B | | | |
| s1 | A도 되고 B도 돼요. 근데 수요일은 5시 전에 끝나야 해요. | 조건부 | A,B | | | 수 17:00 |
| s2 | 셋 다 힘들어요. 화요일이나 목요일 오전이면 됩니다. | 거절 | | 화목 | 오전 | |
| s2 | 정보관에서 하는 걸로 할게요. | 수용 | C | | | |
| s1 | 두 번째 안은 곤란합니다. | 확인 필요 | | | | |
| s3 | 출장 일정 보고 다음 주에 말씀드릴게요. | 확인 필요 | | | | |
| s3 (choice `none`) | 금요일 오전이면 괜찮습니다. | 거절 | | 금 | 오전 | |

### 헷갈릴 때

1. **어느 안인지 모르면 `확인 필요`.** "제안해 주신 시간 괜찮습니다"는 안이 여러 개라 모른다
2. **하나만 어렵다고 하면** 나머지를 고른 게 아니다. "C는 어렵습니다"만 있으면 `확인 필요`. "C는 어렵고 늦은 오후면 좋겠어요"처럼 되는 시간을 말하면 `거절` + 교시
3. **여러 개 고르면 말한 순서대로.** "A나 B" → `A,B`. "B가 더 좋고 A도 돼요" → `B,A`
4. **시각:** 수업은 아침 9시~밤 9시 사이라서 "1시"~"8시"는 오후다. "5시" → 17:00, "4시 반" → 16:30
5. **안 되는 요일만 말하면** 나머지 요일을 적는다. "금요일 빼고 다 돼요" → `월화수목`
6. **요일 없이 "5시 전에 끝나야"** → 다섯 요일 모두: `월 17:00; 화 17:00; 수 17:00; 목 17:00; 금 17:00`
7. **"3시 이후면 돼요"** 처럼 시작만 말하면 → slots `15:00 이후` (= 15:00·16:30·18:00·19:30). **"10시 반이면"** 처럼 정확한 시각이면 그 교시 하나 → `10:30`
8. **고른 안이 이미 시간 조건에 맞아도 시간 조건은 적는다.** "B로 할게요, 수요일은 5시 전에 끝나야 해서요" → `조건부`, `B`, `수 17:00`. 시간 조건은 시스템이 직접 대조하고 다음 차수에도 쓰기 때문이다. 시간 밖 요청은 11번을 따른다
9. **시간표와 상관없는 말**(학회, 조교 부탁, 인사)이나 **질문**("겹친 강의가 뭔가요?")은 라벨에 넣지 않고 memo에 적는다. 판정은 그대로 둔다
10. 그래도 모르겠으면 `확인 필요`로 두고 memo에 이유를 쓴다. 오류 분석에 쓴다
11. **안을 고르면서 붙인 요청은 "학과사무실이 확인하거나 바꿔야 하는가"로 판정한다 (11/22).** 조교가 요청을 놓치지 않게 하려는 규칙이다
    - **조건부:** 강의실을 바꿔 달라는 요청("둘 다 21304로"), 대안에 안 적힌 것이라 확인해야 하는 요청(계단식, 콘센트, 장비, 정원, 앞뒤 빈 시간), 고른 안을 다른 교시로 조금 옮겨 달라는 희망("목요일만 10시 반으로 맞춰 주시면 더 좋겠다"). 꼭이든 "안 되면 그냥 A로"든 같다. 요청은 memo에 적는다
    - **수용 + memo:** 고른 안에 **이미 그렇게 적혀 있는** 요청("강의실 21303 그대로라면요"인데 그 안이 21303), 늘 지켜지는 것(교시 사이 15분 쉬는 시간), 교수님 재량("조금 일찍 끝내도 될까요", "17:30 종료로 조정 가능하면"), 할 수 없는 것("5시 반 시작"처럼 교시에 없는 시각)
    - 이미 충족인지는 **대안에 적힌 요일·시각·강의실로만** 판단한다. 대안에 없는 정보(계단식인지, 장비가 있는지)는 모르는 것이라 조건부다. 시스템도 같은 방식으로 판단한다 (모델은 요청한 강의실 번호만 뽑고, 코드가 고른 안의 강의실과 대조)
    - **시간 칸(days·slots·end_before)에는 "안 맞으면 그 안은 못 쓴다"는 시간만 넣는다.** 옮겨 달라는 희망을 칸에 넣으면 고른 안이 어긋난다고 나와 쓸데없이 다음 차수로 넘어간다. 그 안을 아예 못 쓸 만큼 어긋나면("17:45 종료인데 4시 전에 끝나야") end_before에 적는다
    - "부족하면 C로"처럼 다음 안을 말하면 picks에 순서대로 넣는다 (`A,C`). 배정과 상관없는 말(보강 일정, 프린터, 인사)과 질문은 9번대로 판정을 바꾸지 않는다

### 4단계. 다 달면

시트는 자동 저장된다. 재성이 시트에서 바로 `eval/labels/gold.csv`로 만든다.

## 3부. 정답을 한 명이 단 것의 한계

정답은 재성 한 명이 달았다 (11/21 결정). 두 사람 일치도가 없으므로 보고서에 한계로 적는다.
헷갈린 답장은 memo에 이유를 남겨 두고, 오류 분석에 쓴다. 정하면서 새로 생긴 기준은 이 문서 "헷갈릴 때"에 덧붙인다.

- 평가 명령 (저장소 맨 위에서)
  - 프롬프트 고칠 때: `python eval/run_coord.py reply --method llm --split dev`
  - 최종 숫자: `python eval/run_coord.py reply --method keyword --split test`, `python eval/run_coord.py reply --method llm --split test`
- 파일 위치: 답장 `eval/labels/replies.csv`, 최종 정답 `eval/labels/gold.csv`, 결과 `eval/results/`

| 나오는 숫자 | 뜻 |
|---|---|
| 판정 정확도 | kind가 맞은 비율 (목표 90%) |
| 고른 안 일치 | picks가 순서까지 맞은 비율 |
| 조건 F1 | 요일·교시·종료 시각을 하나씩 비교한 점수 |
| 처리안 일치 | 정답대로 했을 때와 같은 처리안(옮김 / 다음 차수 / 조교 결정)이 나왔는가 |
| 위험 오류 | 거절·애매함을 받아들임으로 잘못 읽은 수. 원하지 않는 시간이 정해질 수 있는 오류 |
| 키워드로 넘어간 건수 | 언어 모델 호출이 실패한 수. 0이 아니면 다시 돌린다 |

언어 모델은 같은 문장에도 답이 조금씩 달라질 수 있다. 보고서에는 날짜·모델 이름이 적힌 결과 파일의 숫자를 쓴다.
