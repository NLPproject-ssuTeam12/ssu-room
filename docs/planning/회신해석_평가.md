# 회신 해석 평가: 측정 이력과 오류 분석

담당: 최재성 (백엔드 2, 조율 NLP) · 작성 2026-11-22 · 결과 파일: `eval/results/`

교수 답장을 **판정**(수용·조건부·거절·확인 필요), **고른 안**(A·B·C, 순서 포함), **조건**(되는 요일·교시, 요일별 종료 시각)으로 바꾸는 `parse_reply`를 평가한다. 비교 기준은 키워드 규칙(시안 v2의 규칙을 옮긴 것)이다.

## 1. 데이터

| 항목 | 내용 |
|---|---|
| 상황 | s1~s20. `eval/make_scenarios.py`가 AI소프트웨어학부 2026-1·2학기 실제 개설 강좌 시간표로 만든다. 과목·분반·강의실·시간은 실제 값, 교수 이름은 가명, 처음 희망·겹친 상대·대안은 꾸민 상황 |
| 답장 | 80개 (팀원 4명 × 20). 교수 역할로 직접 썼고 언어 모델로 만들지 않았다 (`eval/labels/replies.csv`) |
| 정답 | 최재성 한 명이 시트에서 달았다 (`eval/labels/gold.csv`). 가이드는 `docs/planning/라벨링_가이드_회신.md` |
| 나눔 | dev 16개 (프롬프트를 고칠 때 보는 것), test 64개 (`eval/labels/split.csv`) |
| 새 세트 | s21~s25 × 4명 = 20개. 아래 규칙·프롬프트·코드를 다 고친 **뒤** 받은 답장이라 아무도 미리 보지 않은 평가다. 정답도 시스템을 돌리기 전에 달았다 (11/22) |

지표: 판정 정확도, 고른 안 일치(순서까지), 조건 F1(요일·교시·종료 시각 항목 단위), 처리안 일치(`match_conditions`가 내는 행동과 안이 정답으로 낸 것과 같은가), 위험 오류(정답이 거절·확인 필요인데 수용·조건부로 읽은 수).

보조 지표 **받아들임 여부 정확도** (11/22, 결과를 본 뒤 추가): 수용·조건부(고른 안으로 옮김)인지, 거절·확인 필요(시간을 확정하지 않음)인지만 맞혔는가. 판정 4가지 중 수용↔조건부, 거절↔확인 필요를 헷갈리는 건 처리 방식만 조금 다른 싼 오류이고, 두 묶음을 넘는 것이 비싼 오류라서 따로 센다. 위험 오류는 그중 한 방향(안 받아들임 → 받아들임)만 센다.

| 세트 | 키워드 규칙 | 언어 모델 |
|---|---|---|
| test 64 (처음 측정) | 0.656 (42/64) | 0.984 (63/64, 틀린 h20은 나중에 바로잡은 라벨 실수) |
| 새 세트 20 | 0.650 (13/20) | **1.000 (20/20)** |

거절과 확인 필요를 하나로 합치지 않는 이유: 거절은 교수가 말한 조건으로 다음 차수 대안을 자동으로 만들자고 제안하고, 확인 필요는 조교가 직접 처리한다(보류, 질문, 어느 안인지 모름, 한 안만 어렵다고 함). 합치면 보류하거나 질문한 교수에게 답 대신 새 대안을 보내고, 받아들일 수도 있었던 안을 버리게 된다.

## 3. 바꾼 것과 이유

| | 바꾼 것 | 이유 |
|---|---|---|
| ① | 요일 지어냄 방지 검사가 `화목`·`수금`처럼 붙여 쓴 요일도 요일로 본다 | 모델이 맞게 뽑은 요일까지 지우고 있었다 (dev 오류 9개 중 5개). 버그 |
| ② | 답장 해석 결과에 `note`(조교가 확인할 교수 요청) | "계단식 강의실이면요" 같은 요청이 조교 화면에서 사라졌다 |
| ③ | 라벨 규칙 정리 (가이드 8·11번) | 같은 종류의 문장을 어떤 건 수용, 어떤 건 조건부로 달았다. 아래 4절 |
| ④ | 강의실 요청은 모델이 번호만 뽑고 **코드가** 고른 안의 강의실과 대조 | "강의실 그대로라면요"가 이미 충족인지 모델이 판단하면 틀려도 알 수 없다. 코드는 테스트로 확인된다 |
| ④ | 늦은 오후 = 16:30, 18:00 시작은 저녁 | 답장을 쓴 사람들이 18:00 시작을 "저녁"이라고 불렀다 (h01, d01, j10) |
| ⑤ | 고른 안이 종료 조건을 15분 이내로만 넘기면 조건에서 뺌 (`EARLY_END_MIN`) | "17:45 종료인데 17:30에 끝낼 수 있으면"은 교수 재량. 조건으로 받으면 고른 안이 탈락해 다음 차수로 넘어간다. 프롬프트에 적었는데도 모델이 어겨서 코드로 옮겼다 |
| ⑤ | 프롬프트 예시 문구 교체 | "17:30 종료로 조정 가능하면" 같은 예시가 test 답장 표현과 거의 같았다. 80개 답장과 8글자 넘게 겹치는 예시를 없앴다 (평가 답장을 쓰기 전부터 있던 "다시 연락드릴게요" 한 개만 남음) |

## 4. 라벨 규칙 정리 (11/22)

test 오류를 본 뒤 정했다. 그래서 02:10 숫자는 낙관적이다.

- **조건부:** 안을 고르면서 붙인 요청 중 학과사무실이 확인하거나 바꿔야 하는 것 (강의실 변경, 장비·정원처럼 대안에 없는 정보, 다른 교시로 조정 희망). "안 되면 그냥 A로"도 같다
- **수용:** 고른 안에 이미 그렇게 적혀 있는 요청 (대안의 강의실 그대로), 늘 지켜지는 것 (15분 쉬는 시간), 교수 재량 (몇 분 일찍 끝내기), 할 수 없는 것 (교시에 없는 시각)
- 시간 칸에는 "안 맞으면 그 안은 못 쓴다"는 시간만 넣는다

처음 정답과 바뀐 줄 (모두 test): j01·m03·d06·m16 수용 → 조건부, d13 수용 A → 조건부 A,C, j05 조건부 → 수용, h20 고른 안 A → C (라벨 실수). 늦은 오후 매핑 변경으로 m15·d07의 교시에서 18:00이 빠졌다.

## 5. 오류 분석 (02:10 test, 모델 오류 9개)

| 유형 | id | 정답 → 예측 | 처리안에 영향 | 그 뒤 조치 |
|---|---|---|---|---|
| 배정 밖 말을 요청으로 읽음 | m11, j15 | 수용 → 조건부 | 없음 (같은 안으로 옮김) | 프롬프트에 "보강 일정처럼 배정과 상관없는 부탁은 넣지 않는다" |
| 할 수 없는 요청을 조건부로 | d10 | 수용 → 조건부 | 없음 | 프롬프트에 "교시에 없는 시각은 넣지 않는다" |
| 재량 규칙을 어김 | j12 | 수용 → 조건부 + 수 17:30 전 | **있음**: 고른 B가 조건에 어긋나 다음 차수로 넘어감 | 코드로 옮김 (⑤) |
| 고른 안의 시간을 조건으로 다시 적음 | h04 | 수용 A,C → 조건부 A,C + 월목 13:30·15:00 | 없음 | 보류 (진짜 조건과 구분이 어려움) |
| 요일 해석 | j16 | 월목 → 월화목 | 없음 (거절, 다음 차수 조건만 넓어짐) | 없음 |
| 요일 해석 | j13 | 거절 + 다섯 요일 → 확인 필요 | 있음: 조교가 직접 정하게 됨 (안전한 쪽) | 없음 |
| 교시 범위 (정답도 애매) | h01, d07 | 18:00·점심 포함 여부 | 없음 | 없음 |

- 처리안까지 달라진 건 j12, j13 두 건이고, j12는 코드로 막았다. j13은 "확인 필요"로 조교에게 넘어가는 안전한 방향이다
- **위험 오류는 0건**이다. 키워드 규칙은 6건이었다. 예: "C가 괜찮을 것 같긴 한데요… 다음 주 초에 다시 말씀드려도 될까요?"(m06)를 C 수용으로, "B랑 C 중에 하나일 것 같아요… 설문 돌려보고 알려드릴께요"(m09)를 B·C 수용으로, "제시해 주신 세 안은 모두 수용이 어렵습니다"(m10)를 A·B·C 수용으로 읽었다. 거절이나 보류를 수용으로 읽으면 원치 않는 시간이 확정될 수 있다
- 어떤 처리안이든 조교가 [확인]을 눌러야 반영된다. 모델이 틀려도 바로 시간표가 바뀌지는 않는다

dev에 남은 오류 2개 (02:15): m02 (한 안만 어렵다며 다른 시간을 물음 → 정답 확인 필요, 예측 거절), h02 (질문하면서 맡긴다고 함 → 정답 수용, 예측 확인 필요). 사람도 갈릴 만한 문장이라 더 고치지 않았다.

## 5-2. 새 세트 오류 분석 (02:59, 모델 오류 6개)

| 유형 | id | 정답 → 예측 | 처리안에 영향 |
|---|---|---|---|
| 하나만 어렵다는 말을 전체 거절로 | j21 | 확인 필요 → 거절 | **있음**: 다음 차수로 넘어가 교수가 말하지 않은 A·B까지 버림 |
| "넓게 찾아봐 주시고, 이 세 개는 보류"를 거절로 | j25 | 확인 필요 → 거절 + 다섯 요일 | **있음**: 같음. 다만 정답도 애매한 문장 |
| 확인할 요청을 놓침 | d25 | 조건부 B → 수용 B ("세미나실도 같이 잡아 주실 수 있을까요") | 없음 (같은 안). 요청이 조교 화면 note에 안 뜸 |
| 요일 해석 | h25 | 화목 → 다섯 요일 | 없음 (거절, 다음 차수 조건만 넓어짐) |
| 교시 범위 | j24 | "오후면 다 괜찮은데" → 오후 + 저녁(18:00·19:30) | 없음 (같음) |
| 정답이 8번과 어긋남 | m22 | 수용 B,A → 조건부 B,A + 목 16:00 | 없음 |

- **위험 오류는 0건**이다. 키워드 규칙은 3건 (m24 "어떤 강의인지부터 알려 주시면 A로 할지 B로 할지 정하겠습니다" → A·B 수용, h22 질문만 있는 답장 → C 수용, h25 거절 → A·B·C 수용)
- 고른 안은 20개 모두 맞았다. 처리안이 달라진 2건(j21, j25)은 모두 "확인 필요"를 "거절"로 읽은 경우다. 조교에게 묻는 대신 다음 차수 대안을 만들자고 제안하게 되고, 조교가 [수정]으로 바로잡아야 한다
- test에서 고쳤던 유형(붙여 쓴 요일, 몇 분 일찍 끝내기, 이미 충족된 강의실 요청)은 새 세트에서 다시 나오지 않았다. 남은 오류는 test 때와 같은 계열(요일 해석, "확인 필요"와 "거절"의 경계)이다
- **정답 m22·h24는 가이드 8번("고른 안이 이미 시간 조건에 맞아도 시간 조건은 적는다")과 어긋난다.** 둘 다 "○요일은 4시 전에 끝나야"를 수용 + 조건 없음으로 달았다. 결과를 본 뒤 고치면 이 세트도 깨끗하지 않게 되므로 **고치지 않고 그대로 보고한다.** 8번대로 고쳐도 m22는 모델이 맞는 쪽, h24는 틀리는 쪽으로 바뀌어 판정 정확도는 0.80 그대로다

## 6. 한계

- 정답을 한 사람이 달았다. 두 사람 일치도(카파)를 잴 수 없다. 애매한 문장은 memo에 이유를 남겼다
- test를 여러 번 보고 규칙과 프롬프트를 고쳤다. 그래서 새 세트(s21~s25)를 따로 받았다
- 크기가 작다. 새 세트 한 문장이 5%p, test 1.6%p, dev 6.3%p다. 새 세트 0.80은 "처음 보는 답장에서도 0.8 안팎"이라는 확인이지 정밀한 값이 아니다
- 새 세트 답장 중 5개(j21~j25)는 모델이 어디서 틀리는지 아는 최재성이 썼다
- 애매한 정답 한 개(j21)는 AI 도구의 도움을 받아 가이드 규칙을 다시 확인한 뒤 최재성이 정했다
- 답장은 팀원이 교수 역할로 쓴 것이다. 실제 교수 답장과 다를 수 있다
- 모델 출력은 같은 입력에도 조금씩 달라진다 (d12의 "월 15:00"을 한 번은 15:00 하나, 한 번은 15:00 이후로 읽음)
