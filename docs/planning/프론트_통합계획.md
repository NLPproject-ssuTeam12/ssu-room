# 프론트엔드 통합 계획

시연 시안(`docs/prototype/SSU_room_시연_v4.html`)을 실제 사이트로 옮길 때, 저장소의 어느 부분이 어디서 합쳐지는지 정리한다.
작성: 강민우 (프론트), 2026-11-23. 서버 경로·데이터 모양은 [API명세.md](API명세.md)와 [API_조율.md](API_조율.md)를 따른다. 이 문서는 그 둘을 바꾸지 않는다.

## 1. 한 저장소, 폴더별 담당

저장소는 `NLPproject-ssuTeam12/ssu-room` 하나다. 각자 자기 폴더를 브랜치에서 만들고 PR로 `main`에 합친다.

| 폴더 | 하는 일 | 담당 | 프론트와의 관계 |
|---|---|---|---|
| `frontend/` | React 화면 (조교·교수) | 강민우 (`minwoo/frontend`) | **새로 만든다.** 서버 API만 부른다 |
| `backend/app/main.py`, `store.py`, `contracts.py`, `engine.py` | FastAPI 서버, 단계 관리, 데이터 모양 | 김대원 | 프론트가 부르는 유일한 창구 (`localhost:8000`) |
| `backend/app/nlp/coord.py`, `coord_models.py`, `prompts/` | 조율 메시지 쓰기·검사, 회신 해석, 처리안 | 최재성 | 서버를 거쳐서만 쓴다. 응답 모양은 API_조율.md |
| `backend/app/nlp/assistant.py` | AI 도우미 | 김대원 | `POST /assistant`, `/assistant/apply` |
| `solver/`, `backend/app/solver/adapter.py` | CP-SAT 배정 엔진과 서버 연결 어댑터 | 문하윤 | 서버를 거쳐서만 쓴다 (`SSUROOM_ENGINE=solver`일 때 진짜, 아니면 `stubs.py` 가짜) |
| `db/` | SQLite 스키마, 단계·기타 요청 함수 | 문하윤 | 직접 안 부른다. 지금 서버는 메모리(`store.py`)를 쓰고, 나중에 DB로 옮긴다 |
| `eval/`, `data/` | 평가 데이터·결과, 가상 데이터 | 최재성 외 | 화면과 관계없음 |
| `docs/prototype/` | 화면 시안 (단일 HTML) | 강민우 | **설계서 역할.** 실제 사이트에 그대로 들어가지 않는다 |

## 2. 실행할 때 합쳐지는 모양

```
브라우저 (frontend/, Vite, localhost:5173)
   │  fetch (JSON)
   ▼
FastAPI 서버 backend/app/main.py (localhost:8000, CORS는 5173만 허용)
   ├─ store.py ─────────── 상태 (지금 메모리 → 나중에 db/ SQLite)
   ├─ engine.py ─┬─ solver/ (CP-SAT, 문하윤)      ← 없으면 stubs.py 가짜
   │             └─ nlp/coord.py (조율, 최재성)    ← 없으면 stubs.py 가짜
   ├─ nlp/assistant.py ─── AI 도우미 (언어 모델은 서버에서만, 키는 .env)
   └─ export.py ────────── GET /export.xlsx
```

- 프론트는 언어 모델·솔버·DB를 직접 부르지 않는다. API 키도 프론트에 두지 않는다.
- 시안에서 "시연용 흉내"라고 표시한 곳(배정 엔진, 회신 해석, AI 도우미)은 모두 서버 호출로 바뀐다.

## 3. `frontend/` 폴더 구조 (제안)

```
frontend/
  package.json, vite.config.ts      # dev 서버 5173. 서버(8000)는 CORS로 직접 부른다
  src/
    api/client.ts                   # fetch 한 곳. 에러 {detail} 처리, 409·422 메시지 그대로 보여 주기
    api/types.ts                    # contracts.py·coord_models.py와 같은 모양 (Wish, Timetable, Alternative, ReplyParse, Proposal …)
    theme.css                       # 시안의 :root 색 변수 그대로 (라이트·다크)
    components/                     # Timetable(격자), StepsBar, ConfirmDialog, Toast, Chip
    pages/ta/                       # Home, Wishes, Draft, Coord, Final, Settings
    pages/prof/                     # WishInput, PublicTable, Messages
    panels/                         # AssistantPanel, TimetablePanel (오른쪽, 둘 중 하나만 열림)
```

시안의 함수가 옮겨 갈 곳: `vHome`→`Home`, `vWishes`→`Wishes`, `vDraft`→`Draft`, `vCoord`·`decisionBox`·`msgPart`→`Coord`, `vFinal`·`confirmCard`→`Final`, `vPWish`·`paintGrid`→`WishInput`, `vPTable`→`PublicTable`, `vPMsg`→`Messages`, `grid`→`Timetable`, `botPanel`→`AssistantPanel`, `ttDrawer`→`TimetablePanel`.
시안의 `parseReply`·`check`·`genAlts`·`makeDraft`·`botAnswer` 같은 흉내 로직은 **옮기지 않는다** (서버가 한다).

## 4. 화면 ↔ 서버 API

| 화면 동작 (시안) | 서버 호출 | 비고 |
|---|---|---|
| 처음 불러오기, 단계 표시 | `GET /health` (`stage`, `round_no`) | 진행 바 = 희망 수집 / 초안 / 조율 중 / 확정 |
| 분반·강의실 목록 | `GET /sections`, `GET /rooms` | 강의실 정원은 추정값 표시 |
| 교수 희망 입력·저장 | `POST /wishes` | COLLECT에서만 |
| 조교 희망 확인 | `GET /wishes` | 기타 요청(`note`)이 있는 분반을 위로 |
| 초안 만들기 | `POST /draft` → `GET /timetable`, `GET /coord` | |
| 초안 공개 (1차 시작) | `POST /rounds/next` | DRAFT → ROUND 1 |
| 조율 메시지 보내기 | `POST /coord/{id}/message` | 응답 `issues`가 비어야 `sent: true` |
| 교수 답장 | `POST /coord/{id}/reply` | `choice`(A/B/C/none) + `text` |
| 처리안 [확인]·[수정]·[현재대로 유지] | `POST /coord/{id}/decide` | 수정·유지는 사유 필수 |
| 재배정 (다음 차수) | `POST /rounds/next` | 1·2차만. 3차 뒤는 `POST /finalize` |
| 현재 시간표 패널, 대안 미리 보기 | `GET /timetable` + `GET /coord`의 `alternatives` | 미리 보기는 화면에서만 그린다 (서버 호출 없음) |
| AI 도우미 질문·적용 | `POST /assistant`, `POST /assistant/apply` | 적용은 사유 필수 |
| 확정 | `POST /finalize` | |
| 내보내기 | `GET /export.xlsx` | FINAL에서만 |
| 설정 (상대 교수 이름 알리기) | `GET/POST /settings` | |
| 시연 처음부터 | `POST /reset` | |

### 시안 값 → 서버 값 바꾸기

| 시안 (`SSU_room_시연_v4.html`) | 서버 (`contracts.py`) |
|---|---|
| `paint["0-4"] = "희망"` (요일 번호-교시 번호) | `cells["월-15:00"] = "PREFER"` |
| `paint[...] = "불가"` | `cells[...] = "BLOCK"` |
| `must` | `must` |
| `lab: true/false` | `lab: "MUST" / "NONE"` |
| `pref: "정보관"` | `building: "정보관"` |
| `etc` (기타 요청) | `note` |
| `S.assign[id] = {pat, slot, rooms}` | `Timetable.assignments[].blocks` (요일 글자 `"월"`) |
| 대안 `{k, pat, slot, rooms}` | `Alternative {key, meetings:[{day(0~4), start, end, room}]}` |
| `parseReply` 결과 | `ReplyParse` (모양 같음) |
| `check` 결과 | `Proposal` (모양 같음) |

주의: 시간표 `blocks`는 요일 글자(`"월"`), 조율 `meetings`는 요일 숫자(`0`)다 (API명세 `GET /coord` 참고).

## 5. 시안에는 있는데 서버에 아직 없는 것

백엔드와 맞춘 뒤에 붙인다. 정해지기 전에는 화면에서 숨기거나 버튼을 꺼 둔다.

| 시안 기능 | 서버 현재 | 필요한 것 | 상의할 사람 |
|---|---|---|---|
| 최종 시간표 확정 요청 → 교수 [확정] 회신 → 모두 확정하면 내보내기 | 단계가 `ROUND → FINAL` 바로 | 단계 하나 추가(예: `CONFIRM`), 확정 요청 보내기·교수 확정 회신·조교 직접 처리 API, `db/`에 기록할 곳 | 김대원, 문하윤 |
| 조교가 메시지를 **고친 뒤** 보내기 | `POST /coord/{id}/message`가 쓰기·검사·보내기를 한 번에 | 미리 쓰기만 하는 호출 + 고친 `text`를 검사해 보내는 호출 (`check_message` 함수는 이미 있음) | 김대원, 최재성 |
| 회신 도착 알림 (메뉴 숫자) | 없음 | 처음엔 프론트가 몇 초마다 `GET /coord`를 다시 불러 `PROPOSED` 수를 센다. 서버 변경 없음 | — |
| 담당 겹침 (같은 분반을 교수 여럿이 고름) | 분반마다 담당 교수 1명 | 교수가 분반을 고르는 방식이 확정되면 API 추가. 아니면 시안에서 뺀다 | 팀 회의 |
| 교수 희망의 인원 | `Wish`에 칸 없음 | 분반 정보(`/sections`)에 있으면 입력에서 뺀다 | 김대원 |
| 교수·조교 역할 나누기 | 로그인 없음 | 시연은 역할 전환 버튼으로 둔다 | — |
| 회신 해석 방식 전환(키워드/언어 모델) | 요청 본문 `method`로 이미 됨 | 없음 | — |

월·수 / 화·목 묶어 칠하기, 테마, 인쇄, 키보드 이동, 확인창은 화면에서만 하는 일이라 서버와 관계없다.

## 6. 브랜치·합치는 순서

1. 프론트 작업은 `minwoo/frontend`(또는 거기서 딴 `minwoo/fe-<화면>`)에서 한다. `main`에 바로 푸시하지 않는다.
2. 작업 시작 전마다 `git fetch` 후 `git rebase origin/main`(또는 `git merge origin/main`)으로 백엔드 변경을 먼저 받는다.
3. 화면 하나가 서버와 붙어 동작하면 PR 하나로 올린다. 순서 제안:
   1. 뼈대: Vite + React, `api/client.ts`, `GET /health`, 진행 바, 메뉴
   2. 희망 입력(교수)·희망 확인(조교): `/sections`, `/rooms`, `/wishes`
   3. 초안·시간표·현재 시간표 패널: `/draft`, `/timetable`
   4. 조율: `/rounds/next`, `/coord/*`
   5. AI 도우미: `/assistant`
   6. 확정·내보내기: `/finalize`, `/export.xlsx` (확정 요청 단계는 5장 결정 뒤)
4. `contracts.py`, `API명세.md`, `API_조율.md`처럼 여럿이 쓰는 파일은 프론트 PR에서 고치지 않는다. 바꿀 게 있으면 이슈로 담당에게 요청한다.
5. 프론트 확인 방법: 저장소 루트에서 `uvicorn backend.app.main:app --reload --port 8000`, `frontend/`에서 `npm run dev`. 서버는 기본으로 가짜 엔진(`stubs.py`)을 쓰므로 솔버 없이도 화면을 붙일 수 있다.
