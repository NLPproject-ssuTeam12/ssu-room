# solver — 배정 엔진

교수 응답을 읽어 강의 시간표 초안을 만들고, 못 맞춘 과목의 대안을 만드는 배정 엔진입니다(OR-Tools CP-SAT).
DB 스키마와 연결·단계 관리 함수는 `../db/`에 있습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `solver_core.py` | 배정 엔진. 공개 함수 `solve` `alternatives`(= `make_alternatives`) `save_proposal` `finalize` |
| `SOLVER_API.md` | 사용법, 조율 쪽이 넘기는 조건 형식, 값의 뜻 |
| `tests/test_data.py` | 가상 데이터 생성 (70과목, 교수 30명). 응답·희망·분반 수 요청 포함 |
| `tests/test_solver2.py` | 규칙 위반 검사(`verify`), 쌍 제약 검사, 가상 데이터 보조 함수 |
| `tests/run_n1.py` | 전체 풀이 + 연강 응답별 결과 + 분반 연강·교차 |
| `tests/run_n3.py` | 부분 재풀이, 대안 생성(분반 단위·조건), 조율 조건 |
| `tests/run_bd.py` | 요일별 시간대 조건(`by_day`) |
| `tests/run_os4.py` | 두 교수가 한 과목을 맡는 경우(운영체제) |
| `tests/run_sec.py` | 분반 수 합산 11가지 경우 |
| `tests/run_po.py` | 선호 시간 외 불가(`prefer_only`) |
| `tests/run_ph.py` | 서버 단계·기타 요청 확인 함수(`db.py`) 동작 |

## 빠른 시작

```bash
pip install ortools
# 저장소 맨 위에서
python solver/tests/run_n1.py      # 가상 데이터로 풀고 규칙 위반 검사 ('위반: 없음')
python solver/tests/run_sec.py     # 분반 수 합산 (모두 OK)
```

코드에서 부를 때는 `db/`와 `solver/`가 둘 다 `sys.path`에 있어야 합니다(자세한 건 `SOLVER_API.md` 맨 위).

## 용어 (섞어 쓰지 말 것)

| 용어 | 뜻 |
|---|---|
| **주 1회 연강** | 한 분반이 **하루에 2칸을 이어서** 수업. MUST 하루에 이어서 / PREFER 솔버가 고르되 하루에 몰면 보너스 / NONE 1칸씩 이틀 |
| **분반 연강** | 두 분반을 맡을 때 **가반이 끝나자마자 나반** (`BACK_TO_BACK`) |
| **교차** | 분반 연강을 엇갈려서 (가반 월1·목2 / 나반 월2·목1) (`CROSS`) |
| **실습실** | 1 쓴다(실습실만 배정) / 0 안 쓴다 |
| **선호 시간 외 불가** | 희망 칸 안에서만 배정 |

## 솔버 코어 작동 정리

`solver_core.py`가 하는 일입니다. 가중치와 규칙은 현재 코드 기준입니다.

### 1. 전체 흐름

| 단계 | 하는 일 | 함수 |
|---|---|---|
| ① 읽기 | DB에서 과목·교수 응답·강의실·시간 칸·전년 확정본을 읽는다 | `load_input`, `load_history` |
| ② 정리 | 분반 수와 분반별 교수를 정하고, 같은 조건의 강의실을 한 묶음으로 만든다 | `load_input`, `make_classes` |
| ③ 풀이 | 모든 수업 회차에 "어느 칸, 어느 강의실 묶음"을 배정하는 최적화 문제를 푼다 (CP-SAT) | `_solve_model` |
| ④ 호실 배정 | 묶음 안에서 실제 호실을 정한다. 고정된 수업과 이전 호실은 유지한다 | `_assign_rooms` |
| ⑤ 저장 | `timetable`과 `assignment`에 저장하고, 못 놓은 수업 목록을 돌려준다 | `_persist` |

### 2. 입력이 어떻게 쓰이나

| 입력 | 솔버에서의 처리 |
|---|---|
| 교수가 요청한 분반 수 | 교수별로 **더한다**. 가 2 + 나 2는 4분반(1·2=가, 3·4=나). 응답이 없는 교수는 1분반 |
| 조교가 지정한 분반 담당 교수 (`course_section`) | 지정한 번호는 그대로 두고, 남은 개수를 빈 번호에 채운다 |
| 칠한 칸: 불가 (`BLOCK`) | 그 칸에는 절대 배정하지 않는다 |
| 칠한 칸: 희망 (`PREFER`) | 그 칸에 배정하면 보너스. 칠하지 않은 칸은 상관없음 |
| 선호 시간 외 불가 (`prefer_only`=1) | 그 분반은 희망 칸 안에서만 배정한다. 희망 칸이 없으면 적용하지 않고 `unsupported`로 알린다 |
| 실습실 1 / 0 | 1은 실습실에만 배정한다(필수). 0은 실습실을 쓰면 약한 벌점 |
| 주 1회 연강 MUST / NONE / PREFER | MUST는 하루에 연속 2칸, NONE은 1칸씩 이틀, PREFER는 솔버가 고르되 하루에 몰면 보너스 (주당 2칸짜리 수업만) |
| 분반 연강·교차 (`SECTION_PAIR`) | 가반 직후 나반(BACK_TO_BACK), 또는 가1=나2·가2=나1 교시(CROSS). 분반이 정확히 2개이고 1회 1칸일 때만 지원 |
| 응답 없는 교수 | 시간·실습실·연강은 가정하지 않고 자유롭게 놓는다. 건물과 강의실만 전년 확정본에서 가져온다 |

### 3. 반드시 지키는 규칙

| 규칙 | 내용 |
|---|---|
| 강의실 용량 | 한 칸에 한 묶음에서 쓰는 수업 수는 그 묶음의 방 수 이하 |
| 교수 겹침 | 같은 교수는 한 칸에 수업 1개 (분반 담당 교수 기준) |
| 같은 분반 하루 1회 | 한 분반의 회차는 같은 날에 겹치지 않음 (연속 2칸 수업 제외) |
| 같은 학년 필수과목 | 같은 학과·학년의 필수 과목끼리는 시간이 겹치지 않음. 같은 과목의 분반끼리는 겹쳐도 됨 |
| 수용 인원 | 예상 인원보다 작은 강의실에는 배정하지 않음 |
| 전용 강의실 | 특정 학과 전용 강의실은 그 학과 과목만 |
| 불가 칸 | 교수가 칠한 불가 칸 금지 |
| 실습실 1 | 실습실에만 배정 |
| 연속 칸 | 2칸 수업은 같은 날 이어진 칸이어야 함 |
| 분반 연강·교차 | 요청한 모양대로 배정 |
| 선호 시간 외 불가 | 모든 칸이 희망 칸 안에 있어야 함 |
| 고정된 수업 | 일부만 다시 풀 때 건드리지 않는 수업은 그대로 |

### 4. 점수 (낮을수록 좋음)

| 항목 | 점수 | 뜻 |
|---|---|---|
| 못 놓음 | +100000 | 규칙을 모두 지키며 놓을 수 없으면 포기하고 목록에 남김. 사실상 마지막 수단 |
| 이전 배정 유지 | −30 | 다시 풀 때 바뀌는 수업을 최소화 |
| 주 1회 연강 PREFER를 이틀로 나눔 | +12 | 하루에 몰면 보너스 (가중치는 임의 값) |
| 희망 칸에 배정 | −10 (칸마다) | 교수 희망 반영 |
| 전년 같은 강의실 (응답 없는 교수) | −8 | 이력 유지 |
| 희망 건물 순위 | +3 × 순위 | 1순위 3점, 2순위 6점, 목록 밖은 꼴찌+1 |
| 실습실 0인데 실습실 사용 | +5 | 실습실 낭비 방지 |

### 5. 밖에서 부르는 함수

| 함수 | 용도 | 속도 |
|---|---|---|
| `solve()` | 전체 초안 생성. 또는 `free_courses`로 일부 과목·분반만 다시 풀기 | 전체 30~90초 (분반 연강·교차가 많으면 길게). 일부 재풀이 1초 안팎 |
| `alternatives()` | 못 놓은 과목의 대안 N개. 요일·시간대·종료 시각·칸 목록 조건을 받는다 | 15초 제한 |
| `save_proposal()` | 대안을 `proposal` 테이블에 저장 | 즉시 |
| `finalize()` | 시간표를 확정(FINAL)으로 표시. 다음 해 이력의 기준 | 즉시 |

`alternatives()`는 먼저 대상 과목만 움직여 보고, 안 되면 같은 교수나 같은 학년 필수과목도 같이 움직여 봅니다. 현재 배정과 같은 안은 나오지 않습니다. 사용법 상세는 [`SOLVER_API.md`](SOLVER_API.md).

### 6. 솔버가 못 하는 것

| 못 하는 것 | 이유와 처리 |
|---|---|
| 분반 수를 정하는 일 | 교수 요청값을 그대로 쓴다 (의도한 설계) |
| 규칙에 없는 요청 | 실행할 수 없어서 `unsupported`로 돌려주고 조교가 판단한다 |
| 실제로 불가능한 조합 | 예: 분반 교차 + 선호 시간 외 불가인데 인접한 희망 칸이 없는 경우는 `unplaced`로 남아 조율 대상이 된다 |
| 조율에서 받은 조건 저장 | 그 대안에만 적용하고 DB에는 남기지 않는다 |
| 실제 규모 속도 | 가상 데이터(70과목)로만 측정했다 |

## 피드백 반영 현황 (솔버 쪽)

DB 쪽 반영 내용은 `../db/README.md`에 있습니다. "확인됨"은 가상 데이터로 규칙 위반 검사를 통과한 것입니다. 실제 교수 응답이나 실제 강의실 목록으로 해 본 것이 아닙니다.

| 날짜 | 요청 | 상태 | 확인한 것 / 남은 것 |
|---|---|---|---|
| 11/21 | 교수 답장에서 뽑은 조건(`days`, `window`, `end_before`)을 엔진이 그대로 받기 | 반영 (`make_alternatives(condition=…)`) | **확인됨**: 요일 2개 이상/1개, 시간대, 요일별 시간대(`by_day`), 종료 시각, 칸 번호 목록(`slot_ids`) 각각 조건을 지키는 대안 3개 생성. **미확인**: 주 1회 연강 수업(2칸 연속)에 시간대 조건을 같이 쓴 경우 |
| 11/21 | 분반 단위 대안 (`proposal.section_no`) | 반영 | **확인됨**: 분반 단위 대안 생성·저장, 다른 분반은 건드리지 않음 |
| 11/21 | 담당 교수를 분반마다 | 반영 | **확인됨**: 분반별 교수 겹침, 분반 교수 기준 불가 시간·실습실 응답. **미구현**: 조교가 분반 교수를 입력하는 화면 |
| 11/21 | 주 1회 연강 MUST/PREFER/NONE | 반영 | **확인됨**: MUST는 모두 하루 2칸 연속, NONE·미응답은 연속 0개. **미정**: PREFER가 얼마나 강하게 작동할지(가중치 `single_day_prefer`=12는 임의 값, 현재는 PREFER 분반 중 일부만 하루에 몰림) |
| 11/21 → 11/22 | 실습실 MUST/PREFER/NONE → 0/1 | 반영 | 1=실습실만 배정, 0=실습실을 쓰면 약한 벌점 |
| 11/21 | 분반 연강과 주 1회 연강 용어 분리 | 반영 | 같은 과목에 둘을 함께 요청하면 분반 연강을 우선하고 주 1회 연강은 무시(엔진이 `unsupported`로 알림) |
| 11/22 | 교수별 N개 분반 요청을 **더해서** 분반 수 결정 (가 2 + 나 2 = 4개) | 반영 | **확인됨**: 11가지 경우(응답 없음, 1+3, 2+2+1, 조교가 일부 번호 지정, 지정이 요청보다 큰 경우 등). 조교가 `course_section`으로 지정한 번호는 그대로 두고 남은 개수를 빈 번호에 채운다 |
| 11/22 | "선호 시간을 제외하면 수업하기 어렵다" | 반영 | **확인됨**: 켠 분반은 희망(`PREFER`) 칸 안에서만 배정, 대안 생성도 마찬가지. 희망 칸이 없으면 적용하지 않고 `unsupported`로 알린다. 분반 연강·교차와 함께 켜면 정말로 못 놓는 경우가 생긴다(인접한 희망 칸이 없을 때). 이는 오류가 아니라 조율 대상 |
| 11/22 | 시간표 칠하기에서 `AVOID` 제거 | 반영 | 희망 `PREFER` / 불가 `BLOCK`만. `avoid`·`lab_prefer_miss` 가중치 삭제 |

## 알려진 한계 · 남은 일

- 풀이 시간: 분반 연강·교차를 요청한 과목이 있으면 30초에 일부가 못 놓일 수 있다. 60~90초 권장. 실제 규모로는 측정하지 않았다.
- 전년 이력(회신 안 한 교수의 건물·강의실을 전년 확정본에서 가져오기)은 이전 구조에서만 검증했고, 이후 변경 뒤 다시 확인하지 않았다.
- 대안 2단계(같은 교수·같은 학년 필수과목을 움직이는 대안)도 이후 변경 뒤 다시 확인하지 않았다.
- 분반 수는 교수별 요청을 더한 값이다. 솔버는 분반 수를 바꾸지 않는다.
- `prefer_only`의 "선호 시간"은 응답에서 `PREFER`로 칠한 칸이다. 칸 없이 켜면 적용되지 않는다.
- 조율에서 받은 조건(`condition`)은 그 대안 생성에만 쓰이고 DB에 남기지 않는다.
- 분반 연강·교차는 분반이 정확히 2개이고 1회 한 칸일 때만 지원한다.
- 백엔드 연결: `backend/app/solver/`에 서버가 부르는 배정 함수 5개가 필요하다(`backend/app/engine.py` 참고). 지금 `solver_core.py`의 함수 모양과 연결하는 일은 아직 하지 않았다.
