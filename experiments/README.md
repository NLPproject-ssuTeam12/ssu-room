# 배정 비교 실험: 그리디 기준선 vs 배정 엔진 (11/26)

평가 계획의 "배정 — 그리디 기준선과 비교"를 지금 엔진(두 단계 풀이·동점 순서 포함)으로 다시 잰 결과입니다.

## 두 방법

| | 그리디 기준선 (`solver/greedy.py`) | 배정 엔진 (`solver/solver_core.py` `solve`) |
|---|---|---|
| 순서 | 분반을 정한 우선순위대로 하나씩: 실습실 필요 → 가능한 시간이 적은 분반 → 먼저 임용된 교수 → 과목·분반 번호 | 모든 분반을 한 번에 |
| 고르는 기준 | 엔진과 **같은 하드 규칙·같은 점수**로 그때 가장 좋은 칸·강의실 (이미 놓은 분반은 고정) | 같은 규칙·점수로 전체가 가장 좋게, 2단계에서 연강 동선 |
| 다시 고치기 | 없음. 한 번 놓으면 그대로, 못 놓으면 못 놓음 | 전체를 함께 조정 |
| 재배정 | 처음부터 다시 놓음 (이전 시간표를 기억하지 않음) | 이전 시간표 유지 보너스로 다시 풂 (최소 변경) |

두 방법의 차이는 "앞에서 놓은 것을 뒤에서 다시 고치는가"와 "재배정 때 이전 배정을 지키는가" 두 가지입니다. 규칙과 점수는 같습니다(그리디가 엔진 내부 함수를 한 분반씩 불러서 씀).

## 지표
- **초안:** 못 놓은 분반, 하드 규칙 위반(`check_timetable`), 희망 칸을 받은 회차 비율, 희망 건물에 놓인 회차 비율, 19:30 회차, 연강 동선(같은 학과·학년 전공 두 과목이 같은 요일 이어진 교시에 같은 건물인 곳의 수), 걸린 시간
- **재배정:** 초안에서 응답한 분반 10개(시드로 고름)의 교수가 "지금 자리는 안 된다"고 회신했다고 보고 그 자리를 불가로 칠한 뒤 다시 풂. **회신한 10개를 뺀 나머지 분반 중 칸이 바뀐 분반 수**(강의실만 바뀐 분반은 따로)

## 읽는 법과 한계
- **희망 반영:** 엔진이 가상 데이터에서 평균 5.7%p, 실제 데이터에서 2.4%p 더 많은 회차를 희망 칸에 놓았습니다. 그리디는 앞에서 놓은 분반이 나중 분반의 희망 칸을 막아도 다시 고치지 못하기 때문입니다.
- **재배정(최소 변경):** 가장 큰 차이입니다. 엔진은 회신한 분반만 옮기고 다른 분반은 거의 그대로(가상 평균 0.2개, 실제 0개)인데, 그리디는 처음부터 다시 놓아 가상 평균 59.8개(약 60%), 실제 20개가 함께 바뀌었습니다. 차수마다 시간표가 크게 바뀌면 이미 확인한 교수에게 다시 연락해야 합니다.
- **연강 동선:** 가상 데이터에서는 그리디가 더 많았습니다(74.9 대 52.1). 엔진은 교수 희망·건물 점수를 먼저 지키고 그 점수가 같은 범위에서만 동선을 늘리기 때문에(두 단계 풀이), 희망 칸을 더 지킨 만큼 동선을 덜 얻은 것으로 보입니다. 실제 데이터에서는 엔진이 더 많았습니다. 동선을 희망보다 앞에 둘지는 팀 결정 사항입니다.
- **시간:** 그리디가 4~7배 빠릅니다. 엔진도 약 100분반에서 1분 안팎이라 편성 기간(약 두 달)에 비하면 문제가 되지 않습니다.
- **못 놓은 분반:** 두 방법이 같았습니다. 가상 데이터의 일부 시드는 불가 칸이 많아 어느 방법으로도 놓을 수 없는 분반이 있습니다.
- 엔진의 일부 시드는 제한 시간 안에 최적 확인을 못 했습니다(`FEASIBLE`, 시드 3·9·10). 찾은 해는 위반이 없습니다.
- 가상 데이터는 난수로 만든 것이고, 실제 데이터 실험은 1회이며 정원·불가 칸·채플이 가정입니다. 회신은 "지금 자리는 안 된다" 한 가지 모양만 흉내 냈습니다.
- README의 "배정 방식 비교 실험"(중간 발표, 덱 12쪽)은 그때의 엔진·합성 데이터·지표로 잰 결과라 이 표와 숫자가 다릅니다.
